# Bulk session export audit — Midir 48.a baseline

Inspected before changing the format: `front/src/components/SessionPanel.vue`, `utils/batchZip.ts`, `utils/portableReport.ts`, `utils/companionExport.ts`, `utils/reportExportNaming.ts`, `cmd/dilmeterapi/sessionManager.go`, `httpHandlerSession.go`, `summary.go`, `event.go`, the changelog, README and skill/export reference.

- Batch export loads each saved session independently through `/api/sessions/{id}/summary` (not the reduced live summary). It optionally selects one exact character name, exports all targets, and reports missing/failed sessions as skipped. The ZIP name uses the earliest successful recording's local date and encounter families. Entries are root-level sanitized title + sanitized storage filename + `.html`.
- The dependency-free ZIP writer uses UTF-8, STORE, CRC-32, classic 32-bit ZIP offsets and 16-bit entry counts. No manifest, compression, encryption or ZIP64. Sanitized names are not explicitly collision-checked; the aggregate central directory limit needs checking as well as data offsets.
- Each HTML embeds a complete JSON object in `<script type="application/json" id="data">`. It includes `companion` (`format: midir-companion`, `version: 1`), and top-level skill observation, explicit skill-use, positive damage-hit and encounter streams, each with its existing independent version 1. It also contains report views, player/target/HP/skill details, revive data, and scope. The viewer is inline CSS and JS; there are no external dependencies. The payload is **not** the full source NDJSON or a packet capture; it contains the evidence the existing exporter actually exposes. Exact hits and observed activations are separate; historical sessions can legitimately lack exact streams. No application exporter version or durable recording ID is embedded. Companion's session start is Unix seconds; the saved summary exposes start/end Unix seconds (damage bounds).
- `Session.id` is the NDJSON storage filename. Current saves use `session-<save Unix milliseconds>.ndjson`; legacy filenames contain a date/name and may be renamed. The first NDJSON summary event contains mutable title/start/duration/aggregate metadata, not a persistent recording UUID. Existing renames/migrations can rewrite the header while retaining event lines. Neither display title, time alone, filename nor export date is an adequate global identity.
- Repeated inline viewer CSS, markup and JS are unnecessary for Companion. A data-only entry can be the exact same UTF-8 JSON string embedded in HTML (including its existing view data and streams); no alternate combat schema or evidence filtering is needed. Keep the original standalone report and the existing root-level HTML layout as the default. An optimized export reduces only viewer bytes; the gain depends on the recording size and is not a claim about runtime performance. No change to saved combat reconstruction or recognition is needed beyond additive identity metadata.

## 49.a follow-up decision

The earlier data-only choice assumed Companion needed only analytics. Companion also displays the original HTML in its own report viewer; viewer resources are therefore required. 49.a retires data-only production and keeps the original HTML path. Native lossless raw DEFLATE (method 8) reduces the archive without changing the extracted bytes; STORE (method 0) remains the compatibility fallback. The existing manifest, recording identity, and embedded evidence contracts are unchanged. See the current specification and verification results rather than treating the baseline findings above as the current producer contract.
