# Companion 0.3.13 development handoff — Midir 49.a

## Objective

Import Midir bulk ZIPs directly, eliminating the manual unzip step while preserving the exact original HTML reports for Companion's existing embedded viewer and its existing analytics. Midir 49.a produces one universal ZIP containing root `manifest.json` and standalone HTML reports. There is no JSON-only export choice. The manifest and all evidence schemas remain v1; exporterVersion is `49.a`. No network or Midir installation is required. Companion is developed separately.

Read `SESSION-BUNDLE-SPEC.md`, `SESSION-BUNDLE-MANIFEST.schema.json` and `SKILL-AND-EXPORT-REFERENCE.md`. The 49.a specification supersedes the original 49 handoff. The schema retains `report-json` solely for historical 49 archives; support is optional and those archives cannot provide original HTML.

## Implementation tasks

1. Extend the existing file chooser / drop handler to accept `.zip` in addition to existing individual `.html` files. Read ZIPs locally with a ZIP reader supporting STORE (0) and raw DEFLATE (8). Validate directory, unique safe relative paths, counts, sizes, CRC, and reasonable decompressed byte limits, including actual output limits. Never extract to arbitrary disk paths, follow links, or recurse into nested ZIPs. Reject encrypted or unsupported entries. A supported file can have Unicode names. No remote CDN or runtime dependencies.
2. Preflight root `manifest.json`: exact format `midir-session-bundle`, schemaVersion 1, sessionCount and sessions length match, paths resolve exactly, and the archive contains exactly the declared reports plus manifest. Validate IDs, scopes, timestamps, schema values and optional hashes. A present but invalid manifest is an error, not a legacy fallback. If absent, detect existing standalone HTML entries and apply the current HTML importer. Ignore the outer QA delivery ZIP as a nested archive; extract its sample files first.
3. For each `html-report`, decompress to original bytes. Verify CRC and optional file SHA-256 over the uncompressed bytes. Decode UTF-8, extract the exact JSON script text (`<script type="application/json" id="data">`), verify optional payload SHA-256 over the original UTF-8 text, then parse using existing data validation. Do not trim, reserialize, unescape or execute HTML during import. Confirm `exportMetadata` matches the manifest, and confirm evidence schema versions. Use existing `companion` v1 and top-level evidence streams. Do not count aggregate views twice or infer activations from hits. Skip/report retired `report-json` as unsupported if no legacy data-only path exists.
4. **Retain the original complete HTML**, not just extracted JSON. Reuse the same per-file import pipeline and persistent original-report storage used by current individual HTML import; pass the unmodified HTML to the same existing report viewer when opened. Preserve CSS, inline JavaScript, charts, skill highlighting, controls and all other viewer functionality. Do not reconstruct the report from JSON, remove viewer resources, or require companion sidecar files. Keep import parsing inert, and display reports only in an isolated/sandboxed viewing context without privileged native bridges, app-origin storage access or remote fetches. Maintain existing individual-report handling and security boundaries; verify them rather than assuming the new ZIP is trusted because it has a manifest.
5. Deduplicate by stable recording ID and scope (playerId, targetId, sorted unique targetEntityIds). Same ID/scope/payload hash is an exact duplicate; same ID/scope/different hash is a revision, not another run. Different scope is an alternate representation. Do not overwrite full-party/all-target evidence with a narrower import or count variants/revisions twice. Preserve original HTML alongside the chosen representation, including when a previous import lacked HTML. Never replace available original HTML with data-only. Compute hashes locally if absent. `exporterVersion` changes can change payload hashes without changes to damage, and ZIP compression does not change hashes. Older pre-49 exports lack durable IDs: retain the existing legacy fallback. Do not invent identity from encounter names or timestamps.
6. Commit validated entries to local storage; report imported/duplicate/revised/unsupported/rejected counts separately. Avoid reindexing duplicates. Support large batches without silently truncating or freezing the UI; use existing import progress/errors and transactional behavior. The archive is a transport container, not an alternative report format.

## QA matrix (fixture pack)

All current samples are nonempty fictional combat data generated through Midir's actual report functions, not gameplay captures. Unzip the outer fixture pack first. Import `single.zip` and `individual.html`: one identical recording/scope/payload, with byte-identical original HTML. Import `overlap-a.zip` then `overlap-b.zip`: 3 unique recording IDs, 1 duplicate. `standard.zip` and `store.zip` contain identical entries and hashes but different compression. Import either, extract each report and open independently; embedded viewer should match the individual HTML import. `one-player.zip` is an alternate scope of A, not a new run. `legacy.zip` has no manifest. `large.zip` contains 128 reports, including one 6,000-hit recording. `retired-49-json.zip` is the previous optional JSON-only format; reject clearly or import as data-only, never claim it has a viewer. Test duplicate reimports, Unicode, malformed archives, unsupported schemas, corrupt CRC/hashes, resource limits, and offline viewing. Test report controls in Companion itself (encounter selection, hit/skill highlighting, zoom, hover, mobile interactions). No actual Companion code has been modified here.

## Acceptance

One ZIP import action, no manual extraction, same original HTML viewer and analytics as individual import, stable deduplication and offline operation. Users may alternatively extract HTML files with standard ZIP tools and open them individually without Companion. See `SESSION-BUNDLE-VERIFICATION.md` for measured producer results and remaining integrated checks.
